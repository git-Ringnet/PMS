## Dòng 385 - Khôi phục đăng ký và log hủy (booking_cancel_logs)

### TC385-01: Khôi phục đăng ký thì giai đoạn khớp các phòng
| | |
|---|---|
| Chuẩn bị | Ngày hệ thống 1/9 |
| Bước | 1. Tạo đăng ký, phòng A: 1/9 → 1/9 (day use). Lưu. <br> 2. Hủy phòng A bằng nút Hủy phòng. <br> 3. Lấy thêm phòng B: 2/9 → 3/9. Lưu. <br> 4. Xóa đăng ký (chọn lý do). <br> 5. Khôi phục đăng ký, chọn cả phòng A và B. |
| Kết quả mong đợi | Header đăng ký = 01/09 ~ 03/09. Ngày đến/đi các phòng không nằm ngoài giai đoạn đăng ký. |

### TC385-02: Log hủy không ghi trùng
| | |
|---|---|
| Chuẩn bị | Đăng ký 5 phòng, đều tình trạng đăng ký |
| Bước | 1. Hủy lẻ 2 phòng bằng Hủy phòng. <br> 2. Xóa đăng ký (còn 3 phòng). <br> 3. Chạy query: `SELECT cancel_type, booking_room_id, cancelled_at FROM booking_cancel_logs WHERE booking_id = <id> ORDER BY id;` |
| Kết quả mong đợi | Đúng 5 dòng `room` (2 + 3), mỗi `booking_room_id` xuất hiện đúng 1 lần, có 1 dòng `booking`. Báo cáo phòng hủy ra 5 phòng, không phải 7. |

### TC385-03: Xóa đăng ký chưa hủy phòng nào
| | |
|---|---|
| Bước | Đăng ký 3 phòng → Xóa đăng ký → xem `booking_cancel_logs` |
| Kết quả mong đợi | 3 dòng `room` + 1 dòng `booking`. |

### TC385-04: Hủy lẻ rồi hủy nốt các phòng còn lại bằng Hủy phòng
| | |
|---|---|
| Bước | Đăng ký 3 phòng → hủy phòng 1 → hủy phòng 2 → hủy phòng 3 (từng lần) |
| Kết quả mong đợi | Mỗi lần ghi đúng 1 dòng `room` cho phòng vừa hủy. Không dòng nào lặp. |

### TC385-05: Khôi phục một phần phòng
| | |
|---|---|
| Bước | Đăng ký 3 phòng, xóa đăng ký, mở khôi phục và chỉ chọn 1 phòng |
| Kết quả mong đợi | Chỉ phòng đã chọn về tình trạng đăng ký. Header khớp giai đoạn các phòng đang hoạt động. |

### TC385-06: Khôi phục phòng có ngày đến đã qua ngày hệ thống
| | |
|---|---|
| Bước | Hủy phòng có ngày đến nhỏ hơn ngày hệ thống, rồi khôi phục chọn phòng đó |
| Kết quả mong đợi | Báo không đủ điều kiện (ngày đến nhỏ hơn ngày hệ thống), không khôi phục phòng nào đã chọn. |

## Dòng 356 - Lọc Tính phí / Không tính phí (Danh sách công việc → Phòng không đến)

Chuẩn bị chung: 3 phòng đặt trước tới ngày hệ thống. Sang ngày: phòng A noshow **No Charge**, phòng B noshow **Charge Room**, phòng C (nhiều đêm) noshow **Charge Room**.

### TC356-01: Bộ lọc Tính phí
| | |
|---|---|
| Bước | Chọn khoảng ngày chứa ngày noshow → chọn **Tính phí** |
| Kết quả mong đợi | Chỉ có phòng B và C. Phòng A không hiện. |

### TC356-02: Bộ lọc Không tính phí
| | |
|---|---|
| Bước | Chọn **Không tính phí** |
| Kết quả mong đợi | Chỉ có phòng A, cột Tổng tiền = 0. |

### TC356-03: Bộ lọc Tất cả
| | |
|---|---|
| Bước | Chọn **Tất cả** |
| Kết quả mong đợi | Có đủ 3 phòng. |

### TC356-04: Tổng tiền phòng tính phí
| | |
|---|---|
| Bước | Xem cột Tổng tiền của B và C |
| Kết quả mong đợi | B = tiền phòng, C = tiền phòng × số đêm. Không dòng nào Tính phí mà tiền bằng 0. |

### TC356-05: Ô tìm kiếm kết hợp bộ lọc
| | |
|---|---|
| Bước | Chọn **Tính phí**, gõ mã BK hoặc số phòng của phòng B |
| Kết quả mong đợi | Chỉ còn phòng B. Xóa từ khóa thì về B và C. |

### TC356-06: Dòng tổng cuối trang
| | |
|---|---|
| Bước | Đổi 3 bộ lọc và xem "Tổng số phòng", "Tổng đêm vắng" |
| Kết quả mong đợi | Con số đổi theo bộ lọc đang chọn. |

## Dòng 390 - Danh sách phòng đến / phòng đi

Chuẩn bị chung: booking G có 3 phòng đang ở (101, 102, 103). Post tiền phòng cho từng phòng, post thêm 1 dịch vụ cho 102 (VD minibar), post 1 bill vào Phiếu Tổng, thanh toán riêng cho 101 một khoản. Phòng 103 chưa chọn mã giá. Cả 3 phòng có ngày đi = ngày hệ thống.

Trước khi test: mở màn Hóa đơn, ghi lại Tổng DV dòng booking, Tổng DV và Đã TT của từng phòng.

### TC390-01: Số tiền dòng Booking khớp Hóa đơn
| | |
|---|---|
| Bước | Danh sách công việc → tab **Phòng đi** → ngày hệ thống → trạng thái Tất cả |
| Kết quả mong đợi | Tổng DV, Tổng TT ở dòng booking = số dòng master trên màn Hóa đơn (không còn 0 khi Hóa đơn có tiền). |

### TC390-02: Số tiền từng phòng khớp Hóa đơn
| | |
|---|---|
| Bước | Xem cột Tổng DV, Tổng TT từng phòng |
| Kết quả mong đợi | Khớp số của từng phòng trên Hóa đơn (102 có cả tiền minibar, 101 có khoản thanh toán). |

### TC390-03: Bill đã sửa/hủy không bị cộng
| | |
|---|---|
| Bước | Trên Hóa đơn, xóa hoặc sửa 1 bill của phòng 102, rồi tải lại danh sách |
| Kết quả mong đợi | Số tiền phòng 102 giảm đúng bằng bill đã xóa/sửa. |

### TC390-04: Chuyển bill giữa phòng và Phiếu Tổng
| | |
|---|---|
| Bước | Chuyển 1 bill từ phòng 102 lên Phiếu Tổng, rồi tải lại danh sách |
| Kết quả mong đợi | Tổng DV phòng 102 giảm, Tổng DV dòng booking tăng đúng bằng bill đó. Khớp Hóa đơn. |

### TC390-05: Vị trí Tổng DV / Tổng TT trên dòng Booking
| | |
|---|---|
| Bước | Mở trên màn hình laptop, nhìn dòng tiêu đề booking |
| Kết quả mong đợi | 2 số nằm thẳng dưới cột Tổng DV, Tổng TT. Không cần kéo ngang mới thấy. |

### TC390-06: Thu gọn / mở rộng booking
| | |
|---|---|
| Bước | Bấm nút +/- ở đầu dòng booking |
| Kết quả mong đợi | Các phòng thu gọn / mở lại bình thường. Ô tiền trên dòng booking vẫn hiện. |

### TC390-07: Cột Giá phòng ở tab Phòng đi
| | |
|---|---|
| Bước | Xem thứ tự cột |
